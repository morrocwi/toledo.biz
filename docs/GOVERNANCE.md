# Governance and Rights

Toledo Citizen Platform is designed to connect citizens, AI, experts, universities, public institutions, regulators, and market actors without allowing any one layer to erase the citizen's meaning or silently acquire authority it does not have.

## Core non-collapse rules

```text
AI fluency != epistemic warrant
Academic capability != university executability
Referral != handoff != collaboration
Institutional output != citizen outcome
Grant approval != regulatory approval
Government support != independent validation
Problem reframing != permission to replace citizen intent
Experience provenance != legal IP ownership
Company registration != business formation
Innovation success != creator becomes entrepreneur
```

## Three problem representations

Every multi-actor case may contain:

```text
P_C = citizen problem, verbatim
P_S = AI-structured problem
P_D = disciplinary / institutional formulation
```

`P_C` is never overwritten.

When a material reframe occurs, the system records a new version and checks meaning preservation.

## Meaning preservation

A handoff should fail if the downstream formulation silently drops:

- the citizen's goal;
- material constraints;
- risk tolerance;
- unresolved uncertainty;
- relevant context.

The citizen should be able to correct the structured problem before expensive or irreversible work begins.

## Case Steward

The `Civic Knowledge Case Steward` is a coordination role, not an expert authority.

It may be hosted by a trusted intermediary such as:

- a technology clinic;
- a science park;
- a university academic-service unit;
- a community intermediary;
- a public innovation service.

The steward should be authorized to:

```text
transmit case material within consent scope
contact matched capability providers
request status
request a Return Object
trigger fallback/rerouting
log delay or handoff failure
```

The steward may not silently:

```text
change citizen goals
expand consent
claim IP
make professional decisions outside authority
publish confidential case content
```

## Government function types

Do not model "government" as one actor.

```text
G_service
G_funder
G_regulator
G_standard
G_procurement
G_policy
```

Different functions have different authorities and conflicts.

For example:

```text
GrantPass != RegulatoryPass
ProcurementInterest != ScientificValidity
GovernmentFunding != IndependentValidation
```

## Rights decomposition

For knowledge created through several actors, track separately:

```text
experience_provenance
data_rights
inventorship
authorship
IP_ownership
commercial_rights
publication_rights
confidentiality
benefit_sharing
```

No single field should stand in for all rights.

## Experience provenance

The origin of a citizen/community observation should remain traceable even when it is not legally protectable IP.

Minimum provenance record:

```text
originator
original_observation
date
context
contribution_to_problem_definition
contribution_to_solution
use_permissions
attribution_expectation_if_any
```

Provenance is evidence of origin; it is not by itself a legal ownership ruling.

## Benefit-sharing review

When citizen/community experience materially contributes to a commercially valuable result, a benefit-sharing review should be triggered where law, ethics, mission, contract, or community governance makes it relevant.

Possible forms include:

- payment;
- licensing share;
- service access;
- training;
- community reinvestment;
- attribution;
- shared governance.

No universal formula is imposed.

## Data minimization

The Case Passport should contain only what is necessary for the current decision and handoff.

Sensitive raw data should stay in an appropriate private data store. Public GitHub issues and repository files must never be treated as case-data storage.

## Time as a governance constraint

A technically excellent institution may still be the wrong route if it responds after the citizen's real decision window.

The router must record:

```text
decision_window
expected_response_time
interim_safe_action
fallback_route
```

## Mandatory return

A case cannot be closed merely because an institution completed its internal deliverable.

The citizen-facing return must state:

```text
what is known
what is unknown
limitations
recommended next action
unsafe actions to avoid
rights / consent state
follow-up trigger
```

## Exit and appeal

A citizen should be able to:

- withdraw from a route;
- narrow consent;
- reject a reframe;
- request rerouting;
- receive the current case record where appropriate;
- know which obligations survive exit.

## Governance objective

The platform exists to preserve:

```text
Meaning
Continuity
Rights
Responsibility
Time
Return
```

across actors while minimizing unnecessary institutional burden.
