# Toledo Case Lifecycle v0.4

Status: **normative reference contract for the pre-alpha runtime**.

This document defines how one citizen case remains the same case across AI, field observation, experts, universities, public services, regulators and return-to-citizen, even when several decisions coexist inside that one case.

## 1. Core loop

```text
Citizen Problem
    ↓
Create Case Passport
    ↓
Candidate Problem Signature(s) / Barrier State
    ↓
Decision Thread(s)
    ↓
Compile Next Action per active decision
    ↓
World / Human / Institution
    ↓
Record Case Event (optionally scoped by thread_id)
    ↓
Update Case Passport Version
    ↓
Recompile all threads
    ↓
...
    ↓
Citizen Outcome (+ Return Gate when external work was used)
    ↓
CLOSED / STOP
```

The system is event-driven rather than stage-driven.

## 2. Identity and versioning

A case has a stable:

```text
case_id
```

and a monotonically increasing:

```text
version
```

Every accepted event creates the next Case Passport version.

A reroute MUST NOT create a new case solely because one institution is unavailable.

A new Decision Thread also MUST NOT create a new case when it is another decision generated by the same citizen problem and goal context.

## 3. Original problem preservation

The citizen's original wording is:

```text
P_C = citizen_problem_verbatim
```

Normal events MUST NOT overwrite `P_C`.

AI and institutions may add:

```text
P_S = ai_structured_problem
P_D = disciplinary_problem
ProblemSignature = candidate/endorsed routing readout
DecisionThread = decision-specific routing subgraph
```

but:

```text
P_C != P_S != P_D != ProblemSignature
DecisionThread != P_C
```

and the representations remain traceable.

## 4. Problem Signature and practice context

The Case Passport may carry a domain-neutral Problem Signature with multiple candidates, facet-level provenance, known/unknown context, barrier state, optional domain-adapter need, and an endorsed signature only when endorsement is actually recorded.

Occupation or practice history may be stored in:

```text
practice_context
```

but it MUST NOT silently select a bespoke core protocol.

```text
Occupation != ProtocolSelector
Industry != ProtocolSelector
```

See [`PROBLEM_CAPABILITY_GRAMMAR.md`](PROBLEM_CAPABILITY_GRAMMAR.md).

## 5. Decision Threads

A real case can contain several simultaneous decisions at different routing phases.

```text
Case != SingleDecision
```

The Case Passport therefore carries:

```text
decision_threads[]
primary_thread_id
```

Each Decision Thread has its own:

```text
decision
phase
status
problem_signature when needed
observations / unknowns / hypotheses
risk_profile
requested_capability
depends_on
blocking_threads
external_actor_used
latest_return_gate
outcome_state
```

The old fields remain as a backward-compatible projection:

```text
current_phase    = primary_thread.phase
current_decision = primary_thread.decision
```

A legacy case with no supplied threads receives one automatically created primary thread.

See [`DECISION_THREADS.md`](DECISION_THREADS.md).

Many existing events become thread-local when `payload.thread_id` is present. Their semantic meaning does not change.

Country/domain adapters MAY extend local event semantics, but MUST NOT silently change the meaning of these global event names.

## 7. Candidate signature state

`SIGNATURE_CANDIDATES_UPDATED` records candidate translations without promoting them to diagnosis or fact.

`SIGNATURE_ENDORSED` records the selected working signature and citizen endorsement.

`BARRIER_UPDATED` updates one of the reference barrier dimensions:

```text
knowledge
skill
language
tool
resource_time
network
credential
permission
opportunity
unknown
```

with states:

```text
PRESENT
ABSENT
UNKNOWN
```

Unknown is a legitimate state.

The same events may be scoped to a Decision Thread when different decisions require different signatures or barriers.

## 8. Thread dependencies

A thread can declare:

```text
depends_on = [thread_id, ...]
```

The runtime computes:

```text
blocking_threads = {
    dependency | dependency.status not in {CLOSED, CANCELLED}
}
```

A dependent thread with blockers is `BLOCKED`. Its protocol emits:

```text
next_action = HOLD
status = HOLD_FOR_DEPENDENCY
```

unless the thread has its own hard safety/authority trigger, in which case hard escalation remains higher priority.

```text
HardSafetyEscalation > DependencyHold
```

`BlockedThread != FailedCase`.

## 9. Risk updates

`RISK_UPDATED` changes the current risk profile and forces the next compile to reconsider hard escalation.

When `thread_id` is supplied it changes the thread-local risk profile only. Without `thread_id` it remains a shared/legacy case-level risk update.

The reference thresholds are implementation defaults only.

Hard gate state is never averaged into a soft route score.

## 10. Route failure

`ROUTE_FAILED` records:

```text
institution / route
reason
fallback if known
```

while preserving:

```text
case_id
P_C
Problem Signature
Decision Thread identity
observations
unknowns
rights state
history
```

The next compile reroutes from the same Case Passport.

## 11. External-actor state

The lifecycle records external use both at case/legacy level and per Decision Thread:

```text
external_actor_used
```

This state prevents two opposite errors:

```text
forcing a fake external return onto a local citizen+AI thread
```

and:

```text
allowing an externally routed thread to close without returning usable results
```

## 12. Return Object

External work returns through a structured Return Object containing at minimum:

```text
plain-language result
what is known
what is unknown
recommended next action
return gate state
```

The reference runtime independently computes the implementation checks for `TCB-X005`.

A declared `PASS` does not override failed machine checks.

When a Return Object belongs to a specific Decision Thread, the event carries `thread_id`; the Return Gate state is then attached to that thread rather than falsely closing unrelated decisions.

## 13. Thread closure

### Local thread closure

When no external actor was used, a thread may close without an artificial Return Object when:

```text
thread.external_actor_used = false
thread.latest_return_gate = NOT_APPLICABLE
thread.outcome_state ∈ {
    resolved,
    improved,
    safely_held,
    explicitly_rescoped_with_consent
}
thread has no unresolved hard safety/authority trigger
```

### External thread closure

When an external actor was used:

```text
thread.external_actor_used = true
thread.latest_return_gate = PASS
thread.outcome_state ∈ {
    resolved,
    improved,
    safely_held,
    explicitly_rescoped_with_consent
}
```

before setting:

```text
thread.status = CLOSED
```

Thread closure does not itself close the case.

```text
ThreadClosure != CaseClosure
```

## 14. Case closure

Institutional completion alone cannot close a case.

For a legacy single-thread case, the prior local/external closure rules remain backward-compatible.

For a multi-decision case:

```text
RequiredThreadsClosed = TRUE
iff every required non-cancelled thread is CLOSED
```

Case closure requires:

```text
RequiredThreadsClosed = TRUE
AND
outcome_state ∈ {
    resolved,
    improved,
    safely_held,
    explicitly_rescoped_with_consent
}
AND
no unresolved shared hard safety/authority trigger remains
```

before setting:

```text
case_status = CLOSED
```

The Protocol Compiler then emits `STOP` for the closed case/thread views.

This is an implementation of the current Toledo Citizen Closure proposal plus an anchor-preserving multi-decision orchestration rule. It is not a claim that one scalar rule captures every real-world definition of success.

## 15. Reopening

A production implementation SHOULD reopen a closed case only when a material new trigger appears, for example:

```text
problem recurrence
new harm signal
new evidence
regulatory change
citizen requests a new decision
```

A new material decision may also be represented as a new Decision Thread in the same case when the original citizen problem remains the governing context.

The reference runtime currently leaves full reopening policy to the caller rather than silently reopening a closed case.

## 16. Stateless public runtime

The public reference API/MCP server is stateless by design.

```text
caller stores passport
caller sends passport back
runtime returns next version
```

This is not a claim that production systems should lack persistence. It prevents the public reference repository from becoming an accidental sensitive-data service.

## 17. Audit invariant

For any material case transition, an auditor should be able to answer:

```text
What changed?
Which Decision Thread changed?
Who supplied the change?
Which distinction came from citizen, AI, world evidence, or external return?
Which Case Passport version resulted?
Which Toledo equations/predicates informed the next action?
Which other threads block this decision?
Why was the next route selected?
What must return to the citizen?
```

## 18. Non-collapse rules

```text
Case Event != Truth
Problem Signature != Diagnosis
Candidate Signature != Endorsed Signature
Occupation != Protocol Selector
Case != SingleDecision
DecisionThread != NewCase
ThreadPhase != CaseMaturity
BlockedThread != FailedCase
ThreadClosure != CaseClosure
Return Object != Independent Validation
Institutional Output != Citizen Outcome
Route Failure != Case Failure
Case Closure != Innovation Success
Citizen Success != Entrepreneurship
```
