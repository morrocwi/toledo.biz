# Toledo Citizen Platform v0.2.0

Release date: 2026-09-11

Status: pre-alpha executable reference release

## What this release is

v0.2.0 is the first public platform release that packages the Toledo Citizen runtime as a coherent machine-readable and executable system around the existing Toledo v0.17 citizen/cross-actor framework.

The release preserves the existing anchors rather than replacing them. P0–P11, Case Passport, Return Gate, Problem & Capability Grammar, upstream equation authority, and country/domain adapter boundaries remain intact.

## Major additions

### Domain-Neutral Problem & Capability Grammar

The core no longer scales by creating one protocol per occupation or industry.

```text
Occupation != ProtocolSelector
Industry != ProtocolSelector
ProblemSignature != Diagnosis
CandidateSignature != EndorsedSignature
```

AI may generate multiple candidate signatures with provenance, context gaps and barrier states while preserving `P_C = citizen_problem_verbatim`.

### Closed-loop Case Passport runtime

The runtime supports:

```text
Citizen Input
→ Case Passport
→ Case Event
→ Protocol Recompile
→ World / Institution
→ Return Object when external work is used
→ Citizen Outcome
→ STOP or continue
```

The public reference runtime remains stateless; callers hold the Case Passport.

### Anchor-preserved Decision Threads

A single real-world case may now contain several concurrent decisions without collapsing the whole case into one scalar phase.

```text
Case = SharedCaseState + {T1, T2, ..., Tn}
```

Each Decision Thread carries its own phase, evidence, unknowns, gates, capability need, dependencies, route state and closure state.

Legacy `current_phase` and `current_decision` remain as the primary-thread projection for backward compatibility.

Core non-collapse rules:

```text
Case != SingleDecision
DecisionThread != NewCase
ThreadPhase != CaseMaturity
BlockedThread != FailedCase
ThreadClosure != CaseClosure
```

Hard safety/authority escalation outranks ordinary dependency holds.

### API and MCP

- Handoff and Return Gate checks;

## Closure semantics

Local low-risk citizen+AI/world work may close without manufacturing an institutional Return Object when no external actor was used and no hard safety/authority trigger remains.

External routes still require a passing Return Gate plus citizen outcome.

For multi-decision cases, all required non-cancelled threads must be closed before case closure.

## Authority boundary

`morrocwi/toledo` remains the mathematical authority.

`morrocwi/toledo.biz` implements runtime, protocol, schemas, API, MCP, routing data and adapters. Problem Signatures and Decision Threads are runtime/specification architecture and do not by themselves promote or redefine upstream equations.

## Compatibility

This release is intentionally backward-compatible with the prior single-decision Case Passport surface through primary-thread projection.

Production persistence, broad domain validation, security deployment, live institution adapters and large cross-domain falsification are not yet claimed complete.
